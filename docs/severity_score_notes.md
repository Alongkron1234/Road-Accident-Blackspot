# `mart_blackspot_severity` — สูตร severity score (Issue 09 step 1)

## สูตร

```
severity_score = (10 × dead_total) + (3 × injured_severe_total) + (1 × injured_light_total)
                  + (2 × n_accidents)
```

โดย `dead_total`, `injured_severe_total`, `injured_light_total` คือผลรวม (`SUM`) ของอุบัติเหตุ
ทุกครั้งใน cluster นั้น และ `n_accidents` คือจำนวนครั้งที่เกิดอุบัติเหตุใน cluster นั้น (`COUNT(*)`)

## เหตุผลของแต่ละน้ำหนัก

- **10 : 3 : 1** (ตาย : บาดเจ็บสาหัส : บาดเจ็บเล็กน้อย) — อ้างอิงแนวคิด EPDO (Equivalent Property
  Damage Only) ที่หน่วยงานจราจรใช้กันทั่วไป ให้น้ำหนักสูงมากกับการเสียชีวิตเทียบกับบาดเจ็บระดับอื่น
- **`SUM` ไม่ใช่ `AVG`** — เลือกผลรวมเพราะต้องการสะท้อน "ผลกระทบสะสมทั้งหมด" ของจุดนั้น ตรงกับ
  เจตนาของ "จุดเสี่ยง" (blackspot) ที่อยากรู้ความเสียหายรวม ไม่ใช่ความรุนแรงเฉลี่ยต่อครั้ง
- **`+ 2 × n_accidents`** — ถ้าไม่มีท่อนนี้ cluster ที่เกิดอุบัติเหตุถี่มากแต่ไม่มีผู้เสียชีวิต/
  บาดเจ็บสาหัสเลย (เช่น รถชนท้ายเบาๆ ซ้ำๆ) จะได้คะแนนต่ำมาก ทั้งที่ความถี่ที่สูงผิดปกติก็เป็น
  สัญญาณอันตรายที่ควรจับตาด้วย — ท่อนนี้ให้ "ความถี่" มีน้ำหนักเป็นของตัวเอง แยกจากความรุนแรง
- **น้ำหนักความถี่ = 2** — ตั้งค่าปานกลาง (น้อยกว่าน้ำหนักบาดเจ็บสาหัสแต่มากกว่าบาดเจ็บเล็กน้อย)
  เพื่อไม่ให้ cluster ที่เกิดบ่อยแต่ไม่ร้ายแรงแซงหน้า cluster ที่มีผู้เสียชีวิตจริงได้ง่ายเกินไป
  ยังไม่ได้ทดสอบปรับค่านี้กับข้อมูลจริง จะปรับต่อได้หลัง `dbt run` ถ้าผลลัพธ์ (step 4 ของ
  PLAN.md) ดูไม่สมเหตุสมผล

## ตัวเลือกที่พิจารณาแต่ไม่เลือก

- **KABCO/EPDO scale แบบเต็ม** (ที่ใช้น้ำหนักสูงมาก เช่น fatal=545 เทียบ PDO=1) — ซับซ้อนเกินความ
  จำเป็นสำหรับโปรเจกต์นี้ และตัวเลขจริงอ้างอิงจากบริบทสหรัฐฯ ไม่ตรงกับข้อมูลไทย
- **ไม่ใส่น้ำหนักความถี่เลย (severity sum อย่างเดียว)** — ถูกตัดออกเพราะจะพลาด cluster ที่เกิดบ่อย
  แต่ไม่ร้ายแรง ซึ่งยังถือเป็นความเสี่ยงที่ควรแสดงผล
